## 2. Cambios técnicos

### Botón START por etapa (Refactor StageManager)

**Antes:** `stage_started` → spawn directo.
**Ahora:** 2 fases por stage:
- `stage_pending(data, idx)` → World limpia + aplica layout + tint, PERO NO spawn. Banner muestra START button.
- `stage_started(data, idx)` → spawn enemies. Banner fade out.

Métodos nuevos del StageManager:
- `request_combat_start()` — el botón START lo llama. Emite `stage_started`.
- `is_pending()` — true entre `stage_pending` y `request_combat_start`.

El flow auto-advance después de `stage_cleared` también vuelve al estado pending (no salta directo a combate).

### Visuals de armas (StickFigure refactor)

`StickFigure` ahora soporta 2 armas visibles simultáneamente:
- `weapon_main: WeaponType` — mano frontal. Sigue swing en ATTACK.
- `weapon_off: WeaponType` — mano trasera. Típico para Shield.

`enum WeaponType { NONE=0, SWORD=1, BOW=2, STAFF=3, HAMMER=4, SHIELD=5 }`

5 funciones `_draw_<tipo>()`:
- **Sword**: hoja + guarda + empuñadura. Hoja barre de -0.55π a +0.55π en attack.
- **Bow**: arco curvo (2 segmentos) + cuerda. Cuerda se tensa hacia atrás según `swing_progress`.
- **Staff**: bastón + cristal en la punta. Cristal crece de 3.5 a 5 en attack.
- **Hammer**: mango grueso + cabezal rectangular grande. Sigue swing.
- **Shield**: óvalo con boss central. Sin animación.

Color de armas: por default un gris claro. `weapon_color` override desde fuera. `weapon_scale` = 1.0 normal, 1.4 para R4 boss.

### Player aplica visual de arma equipada

`player.gd._refresh_weapon_visuals()` se conecta a `InventorySystem.equipped_changed`. Lee equipped(ARMA) → `weapon_main` y equipped(ESCUDO) → `weapon_off`.

`ItemData` tiene nuevo `@export var visual_type: int` (0-5 según `WeaponType`). Items existentes actualizados:
- espada_madera.tres → `visual_type = 1` (Sword)
- escudo_tablones.tres → `visual_type = 5` (Shield)
- tunica_aprendiz.tres → `visual_type = 0` (None — la armadura no se renderiza extra)

### Armas en enemies por clase

`enemy.gd._weapons_for_class(c)` retorna `[main, off]`:
- Melee → `[Sword, None]`
- Tank → `[Hammer, Shield]`
- Archer → `[Bow, None]`
- Mage → `[Staff, None]`

Se aplica en `_ready()` después de stats. R4 además: `weapon_scale = 1.4` + aura.

### Aura partículas R4 boss

`enemy.gd._spawn_boss_aura()`: GPUParticles2D procedural:
- 28 partículas, sphere emission radius 22, lifetime 1.4s, preprocess 0.6s.
- Sube lento (gravity Y -25), velocidades 10-25, escala 0.4-1.0.
- Gradient dorado intenso → dorado transparente.
- z_index -1 (detrás del cuerpo).
- Apagada en `_on_died` (no liberada — el enemy queda como cadáver).

### Layouts distintos por etapa

Nuevo Resource `StagePlatformConfig`:
```gdscript
@export var position: Vector2
@export var size: Vector2 = Vector2(200, 20)
@export var color: Color = Color(0.30, 0.22, 0.16, 1.0)
```

`StageData` ahora tiene:
- `platform_overrides: Array[StagePlatformConfig]` — si NO vacío, oculta defaults y crea nuevas.
- `hide_default_platforms: bool` — si true Y overrides vacío, igual oculta (arena limpia).
- `show_decorations: bool` — controla visibilidad del Node2D "Decorations" (árboles, luna).

`world.gd`:
- Cachea `_default_platforms` en `_ready` (children en grupo "platform").
- Cachea `_decorations: Node2D` (referencia al nodo).
- `_apply_platforms(overrides, hide_default)` arma/oculta según lógica.
- `_apply_decorations(show)` toggle `.visible`.
- `_build_platform(cfg)` crea StaticBody2D + CollisionShape2D + 3 ColorRects (top grass, body, shadow) para parecerse a las defaults.

Layouts MVP:
- **E1**: defaults (3 plats horizontales — el world.tscn original).
- **E2**: 4 plats en zigzag (-450/-100, -100/-220, 250/-150, 560/-260) tinte cyan suave.
- **E3**: 5 plats dispersas con verticalidad mayor (alturas -80 a -280) tinte violeta.
- **E4 boss**: arena limpia. `hide_default_platforms=true`, `show_decorations=false`. Sin nada visual extra — solo el Guardián.

### Fix hitbox facing player

Bug viejo: `hitbox.position.x = abs() * current_facing` solo se hacía en `_start_attack()`. Si girabas sin atacar, la hitbox quedaba del lado del último ataque.

Fix:
- Nuevo método `_apply_facing(dir)` en `player.gd`. Actualiza `current_facing`, `sprite.set_facing()`, y reposiciona hitbox.
- Llamado desde `_handle_input` cuando `new_facing != current_facing`.
- Llamado defensivamente desde `_start_attack` (por las dudas).

## 6. Decisiones tomadas en esta sesión (sin preguntar)

1. **Botón START requiere click manual** — el banner queda visible hasta que se aprieta. NO se cierra automáticamente. Decisión: dar tiempo ilimitado para equipar.

2. **NO pause global durante `stage_pending`** — el player puede caminar y mover cámara mientras el banner está visible. Razón: el InventoryScreen ya hace su propio `paused=true`. Conflictos si stage también pausa.

3. **`weapon_off` para Shield en mano trasera**. Razón: los items shield ya están en slot ESCUDO. Mapeo natural: ESCUDO → weapon_off → renderiza Shield en el brazo trasero.

4. **`visual_type` para Armadura = 0 (None)**. La armadura no se renderiza como arma extra; se "siente" en stats pero no agrega un visual al StickFigure (el `body_color` del StickFigure ya cumple esa función).

5. **9 items nuevos cargados todos a la mochila al spawn** del player. Decisión de testeo: queremos que Leo pueda probar todas las visuals + rarezas sin tener que farmear drops. Eventualmente los items NO se cargan default — se obtienen como loot.

6. **Aura R4 es procedural (no .tres de Particle Material)**. Razón: más controlado desde código + no agrega más assets. Se crea on-demand en `enemy.gd._ready()` cuando rarity==R4.

7. **`hide_default_platforms` separado de `platform_overrides=[]`**. Hubo opción de "si overrides vacío Y is_boss=true → ocultar". Preferí flag explícito para no acoplar lógica de boss con layout.

8. **Layouts no incluyen Y de spawn distintos por etapa**. Los enemies siguen spawneando a Y=-50 (sobre el suelo). Si querés enemies en plataformas, hay que extender `EnemySpawnEntry` con un `position_override` o un sistema de spawn points por layout. NO implementado todavía.

9. **Player arranca SIN nada equipado**. Confirmado del handoff anterior. Los 12 items van a mochila, equipar es manual. Refuerza el botón START — Leo equipa antes de pelear.

## 7. Riesgos conocidos / cosas a vigilar

⚠️ **Critical:**

1. **Si `Gradient.set_color(idx)` falla** porque el Gradient nuevo no tiene punto en ese índice → cambiar a `gradient.add_point(0.0, color)` y `add_point(1.0, color)` (más explícito).

2. **El `_default_platforms` se cachea SOLO en _ready**. Si Leo agrega/quita plataformas en `world.tscn` después y guarda, el cache podría quedar desfasado. Mitigation: cerrar el juego y reabrir.

3. **El botón START usa `mouse_filter` STOP del Button. Si TouchControls está encima con z mayor, podría bloquear los taps** del START. El layer del banner es 25 y el HUD es 10 — banner queda arriba. Pero los TouchButton son z_index dentro del HUD CanvasLayer (10). Botón START como hijo de banner (layer 25) debe recibir el evento primero. **Validar.**

⚠️ **Medium:**

4. **Boss aura con 28 partículas en mobile**. GPU particles son baratas pero 28 + 4 enemies en pantalla podría caer FPS en mid-range Android. Test en hardware real. Si lagueá, bajar `amount` a 16.

5. **`enemy.gd` tiene un setter del `enemy_class` que **NO existe** para `rarity`**. El world.gd hace `if "rarity" in enemy: enemy.rarity = rarity`. El check `in` verifica si la propiedad existe — Godot 4 tiene esto OK para `@export var`. Pero si llega a fallar, los enemies spawnearían con rarity=0 (R1).

6. **Backup pre-refactor de `world.gd` y `enemy.gd`** NO se creó. Si algo se rompe, hay que git-revertir (asumiendo que Leo eventualmente init'ee git — del handoff anterior es pendiente).

⚠️ **Low:**

7. **El Banner START aparece SIEMPRE al inicio**. No hay forma de "skip" la primera vez. Si Leo quiere arrancar el combate inmediato (debug rápido), tendría que apretar START primero. Considerar atajo de teclado SPACE = confirm.

8. **El layout de E2 y E3 tienen plataformas TAN altas que algunos enemies podrían quedar atrapados**. El multi-hop AI debería resolverlo, pero puede pasar que un Tank salte mal y se quede. Vigilar.
