## 1. Lo que se hizo en esta sesión

Implementación del **Sistema de Etapas** completo. Antes el world spawneaba N enemies fijos al inicio y listo. Ahora:

> Etapa 1 → matar todos → etapa 2 más fuerte → etapa 3 con más variedad → etapa 4 (BOSS R4) → run completada.

Toda la config es **data-driven** vía `StageData.tres`. No se toca código para cambiar etapas.

### Features nuevas

| Feature | Archivo | Qué hace |
| :--- | :--- | :--- |
| **EnemySpawnEntry** | `scripts/data/enemy_spawn_entry.gd` | Resource: `enemy_class + rarity + count`. Cada entry = N enemies de clase X con rareza Y. |
| **StageData** | `scripts/data/stage_data.gd` | Resource de una etapa: `display_name`, `subtitle`, `spawns: Array[EnemySpawnEntry]`, `is_boss`, `ambient_tint`. |
| **Rareza enemy R1-R4** | `scripts/systems/game_config.gd` | `enum EnemyRarity`. Mults HP/DMG/telegraph por rareza. Tinte de color y escala de sprite. Helpers `enemy_*_with_rarity()`. |
| **StageManager** | `scripts/systems/stage_manager.gd` (autoload) | Orquesta progresión: trackea `alive_count`, escucha `health.died` de cada enemy, avanza a la siguiente stage con delay de 1.5s. Signals `stage_started`, `stage_cleared`, `run_completed`. |
| **World stage-driven** | `scripts/world/world.gd` (REFACTOR) | Hook `stage_started` → cleanup + spawn + ambient tint. Hook `run_completed`. Fallback "playground mode" si stages está vacío. `auto_load_default_stages = true`. |
| **StageBanner UI** | `scripts/ui/stage_banner.gd` + `scenes/ui/stage_banner.tscn` | CanvasLayer encima del HUD. Muestra "ETAPA N/4 — Nombre" con fade in/out al `stage_started`. "ETAPA COMPLETADA" verde al `stage_cleared`. "VICTORIA / ZONA COMPLETADA" dorado al `run_completed`. Boss → texto más grande dorado. |
| **4 stages MVP** | `resources/stages/zona1_etapa_[1-4].tres` | Etapa 1: 3 melee R1. Etapa 2: 3 melee + 2 tank R2. Etapa 3: 3 melee + 3 tank + 2 archer + 2 mage R3. Etapa 4: 1 tank R4 (boss placeholder). |
| **Doc feature** | `docs/features/world/stages_system.md` | Doc completa: qué hace, pilares reforzados, integración, decisiones, cómo testear, pendientes. |

## 4. Cómo testear in-game

1. Abrir Godot 4.6, ejecutar `scenes/world.tscn`.
2. **Validar etapa 1**: banner "ETAPA 1 / 4 — AVANZADA DE VANGUARDIA" aparece arriba al cargar. 3 enemies melee rojos comunes.
3. Matar los 3 → banner "ETAPA COMPLETADA" verde → tras 1.5s, "ETAPA 2 / 4 — PELOTÓN DE GUARNICIÓN".
4. **Validar etapa 2**: 5 enemies con tinte cyan. Más HP/DMG. Background con tono ligeramente azulado.
5. Matar los 5 → etapa 3.
6. **Validar etapa 3**: 10 enemies violeta (3 melee + 3 tank + 2 archer + 2 mage). Tank R3 telegrafía 0.55s (era 0.50). Mage R3 dispara con tinte violeta.
7. Matar los 10 → etapa 4.
8. **Validar BOSS**: banner "BOSS — GUARDIÁN DE LA MALEZA" texto más grande dorado. 1 tank R4 dorado, mucho más grande (sprite 1.45×). Telegraph 0.80s. HP 4.5× del base. Pega como un mazo (2.2× DMG).
9. Matarlo → banner "VICTORIA / ZONA COMPLETADA" dorado, dura ~4s.

### Variar config sin tocar código

Abrir `resources/stages/zona1_etapa_X.tres` en el editor de Godot. Cambiar `count`, `rarity`, `enemy_class` de cualquier entry. Guardar. Re-ejecutar — cambio inmediato.

### Playground mode (testear 1 stage manual)

Si querés iterar una sola configuración rápido sin tocar `.tres`:
1. En `world.tscn`, vaciar el array `stages` (clear).
2. Desactivar `auto_load_default_stages` (uncheck).
3. Editar `GameConfig.TEST_*_COUNT` para definir el spawn.
4. El world spawneará con esos counts y NO progresará — sin StageManager, sin banner.

## 6. Decisiones tomadas en esta sesión (sin preguntar)

1. **StageManager como autoload**, no como nodo en world. Sobrevive a reload de scene. Patrón consistente con MomentumSystem / InventorySystem.
2. **Pausa de 1.5s entre stages** (`ADVANCE_DELAY_SECONDS`). Para respirar + leer banner.
3. **Boss = tank R4 escalado** como placeholder. Por ahora alcanza para validar el bucle "stage final → boss → run completada". Boss propio queda como pendiente.
4. **Tinte de rareza multiplicativo** sobre el color de clase (no overlay). Refuerza identidad de clase + diferenciación de rareza sin pisar.
5. **Escala sprite por rareza** (R4 = 1.45×) — afecta SOLO al visual, hitbox/hurtbox/velocidad se mantienen consistentes con la clase.
6. **4 stages MVP fijas** en `resources/stages/zona1_etapa_[1-4].tres`. La "zona 1" es la única del MVP — futuras zonas tendrán su propio set.
7. **`auto_load_default_stages = true`** por default. Si Leo no asigna nada en el editor, el world igual arranca con la run completa.
8. **Banner NO pausa el juego.** Es indicativo. El combate sigue de fondo durante la transición (aunque no haya enemies vivos).

## 7. Riesgos conocidos / cosas a vigilar

⚠️ **Critical:**
1. **Reload de scene puede duplicar connects al StageManager.** Si Leo prueba "Reload Current Scene" o navega entre escenas, los signals `stage_started.connect(_on_stage_started)` se duplican en el autoload. Va a fallar con "Already connected" o ejecutar handlers viejos sobre nodos free'd. Mitigation futura: añadir `if not StageManager.stage_started.is_connected(...): connect(...)`. Hoy solo importa si hay reloads.

2. **Bug recurrente del handoff anterior**: Godot al guardar puede regenerar nodos viejos en `world.tscn`. Si reaparece `Enemy` hardcodeado o `TouchControls2`, eliminar manual.

⚠️ **Medium:**
3. **Formato `.tres` de stages no validado en Godot todavía.** Usé `spawns = [SubResource(...)]` (sintaxis del `espada_madera.tres`). Si Godot 4.6 prefiere `Array[ExtResource("2_entry")]([...])` para typed arrays, hay que cambiar los 4 .tres. Fácil fix si aparece el error.

4. **`scene_world.tscn` perdió el ext_resource `2_enemy`** (no se importaba más). El instance node también se removió. Si Godot pide "missing dependency" al abrir, cerrar el editor antes de inspeccionar.

5. **Sprite scale por rareza puede romper hitbox visual.** El scale solo afecta al StickFigure (sprite). La hitbox queda igual que R1 — daño consistente pero hay disonancia visual: un R4 grande pega con el mismo rango que un R1 chico. A futuro: mejor diseño que solo escalar.

6. **No hay clamp del color por canal individual al multiplicar tinte.** Está clampeado a [0, 1] en `enemy.gd._ready()`. Si Leo sube los multiplicadores RARITY_TINT > 1.3, puede quedar washed-out. Probado para los valores actuales (0.5-1.3), OK.

⚠️ **Low:**
7. **Banner usa `process_mode = ALWAYS`** y NO pausa el juego. Si en el futuro Leo pausa el juego con el inventario en medio de un `stage_started`, el tween del banner sigue corriendo. Cosmético.
