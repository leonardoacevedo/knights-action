## 1. Lo hecho esta sesión

### Hotfix #1 — `PlayerProgression.get_tree()` chocaba con `Node.get_tree()`
Error reportado al cargar:
```
Línea 134: get_tree() overrides a method from native class "Node"
```
Fix: renombrado a `get_skill_tree()` en `player_progression.gd` + 5 callsites en `skill_tree_screen.gd`. **Lección documentada en sugerencias.md:** agentes nunca deben pisar APIs nativas de `Node`.

### Hotfix #2 — Inferencia de tipo en `skill_tree_screen.gd`
Error:
```
Línea 917: Cannot infer the type of "col" variable
```
Fix: tipar `var branch_colors: Array[Color]` (2 ubicaciones) + `var col: Color`. **Lección:** evitar `:=` con literales `[...]` mixtos.

### T33 — F3-5: XP-on-kill (`progression-system`)
**Implementado:**
- `GameConfig.xp_for_kill(rarity)` — R1=10, R2=25, R3=60, R4=300.
- `ExperienceSystem` autoload (patrón `DropSystem`).
- `world.gd._spawn_stage` registra cada enemy con su XP al instanciarlo.
- `game_over_screen` resetea XP system **pero NO el progreso del personaje** (decisión: nivel persiste entre runs).
- `XpToast` + `XpToastContainer` UI top-left dorado con stacking.
- `LevelUpBanner` centro pantalla con overshoot scale (0.5→1.1→1.0).
- Tests: 4 estáticos + 4 integración documentados.

**Decisión clave:** NO multiplicar XP por Momentum. Momentum ya multiplica drops (×2) y Furia (×1.5); XP debe sentirse como "progresión del personaje", no farmeable adicional.

## 6. Decisiones canónicas establecidas

1. **XP NO multiplica por Momentum** (nivel = progresión, no farmeo).
2. **Progresión persiste entre Game Over** (es del personaje, no de la run).
3. **Naming:** nunca pisar APIs nativas de `Node` (`get_tree`, `get_parent`, etc). Prefijar (`get_skill_tree`).
4. **Tipos explícitos en arrays:** `var x: Array[T] = [...]` vs `var x := [...]`.
